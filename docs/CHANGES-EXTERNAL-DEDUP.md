# Скрытие дублей Yealink + Active Directory

> Историческая заметка для workspace 0.2.24. Актуальное поведение описано в README.md, DEPLOYMENT.md и CHANGELOG.md.

База: GitHub `main`, версия **0.2.24**.  
Дата: 20.11.2026.

## Правило

Внешняя запись Yealink не попадает в кэш, если одновременно:

1. нормализованное **ФИО** совпадает с AD-сотрудником;
2. совпадает **любой непустой параметр**:
   - e-mail;
   - внутренний, внешний или мобильный телефон (сравниваются цифры);
   - должность;
   - подразделение;
   - организация;
   - кабинет.

Совпадения только телефона или только имени недостаточно — нужна пара
«ФИО + параметр». Запись с тем же именем, но без общих контактов, остаётся:
это может быть другой человек.

## Настройка

В настройках внешнего телефонного файла есть переключатель
**«Скрывать дубли AD»** (`settings.externalHideDuplicates`).

- включён (по умолчанию) — записи Yealink, дублирующие AD, не попадают в кэш;
- выключен — дубли остаются в справочнике и поиске;
- переключение сразу сохраняет `externalHideAdDuplicates` и, если внешний
  справочник включён, перечитывает файлы — список обновляется без перезапуска;
- значение входит в `config.json`, `kmaruda-config.json` и embedded-профиль.

Поле в конфигурации:

```json
"externalHideAdDuplicates": true
```

## Где применяется

- `Db::ad_duplicates()` — выборка AD-контактов с раскрытыми названиями
  подразделения/организации/кабинета.
- `external::is_ad_duplicate()` — сравнение.
- `external::refresh()` — фильтрация записей перед `replace_external_sources`,
  поэтому дубли не попадают ни в БД, ни в интерфейс, ни в поиск.
- `SyncManager::run()` после AD-синхронизации повторно перечитывает внешние
  файлы, чтобы отсечь сотрудника, которого не было в кэше на момент первой
  загрузки файла.

## Ограничения / что проверить

- Сравнение ФИО точное после `collapse_spaces + lowercase`; сокращения и
  перестановка слов не считаются совпадением.
- Телефоны сравниваются по цифрам, форматирование не важно.
- При большом AD и большом Yealink текущая проверка — O(AD × Yealink). Для
  целевых объёмов приемлемо; при необходимости можно построить индекс по
  нормализованному имени.
- Дубли, уже лежащие в кэше от старой версии, исчезнут после ближайшего
  обновления внешнего файла (ручного или автоматического).
